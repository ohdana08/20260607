2026-09-17. **검토 대상 성능 후보의 로컬 검증 통과.** Architect의 설계, Implementation의 수정, Reviewer의 독립 검토, SRE/Optimizer의 독립 측정과 수정 후 재검증을 완료했다. 이번 판정은 직전 성능 개선 4개와 추가 마감일 필터 수정에 한정한다. 작업본에 누적된 모든 기능의 운영 검증이나 배포 승인을 뜻하지 않는다.

이번 팀 단계에서 새로 수정한 제품 파일은 `lib/data/openFilter.ts`다. 직전의 인증 검증 중복 제거, 지역 정규식 재사용, 조회 컬럼 제한, 캐시 승격 수정은 유지하며 다시 검토했다. [제품 5개 변경 패치](team-final-changes.patch)는 각 최적화 직전 보존본을 기준으로 한다. 다른 운영 모듈·RCA·확장 설계의 누적 변경 전체 패치가 아니다.

## 성능 결과와 해석 범위

합성 공고 3,000개를 사용해 실제 `fetchOpenPrograms → matchByButtons` 함수를 실행했다. 각 프로필·버전당 4회 × 20개 측정 표본이며 워밍업은 따로 저장하고 제외했다. 비교 기준은 직전 4개 최적화가 이미 반영된 팀 검토 시작 시점이다.

| 프로필 | 수정 전 p95 | 수정 후 p95 | 감소율 |
|---|---:|---:|---:|
| 부산 | 62.661ms | 10.143ms | 83.8% |
| 경기 | 58.956ms | 9.331ms | 84.2% |
| 전국 | 61.440ms | 9.282ms | 84.9% |

추천 결과와 순서는 모두 같았고 프로필별 4회 측정 모두 30% 감소 기준을 넘었다. 공고 조회당 날짜 표시 도구 생성은 2,400회에서 0회로 줄었다. 수정 후 최초 모듈 로딩 때는 1회 생성한다.

이 수치는 단일 Mac의 로컬 함수 처리 시간이다. 공고 데이터 전송은 합성 데이터 복제로 대체했으므로 운영 HTTP 지연·동시접속 처리량·100배 트래픽 검증으로 확대하지 않는다. 메모리 관측값은 실행 이력과 측정기 영향을 받으므로 메모리 절감도 입증하지 않는다. 실제 운영 DB 실행 계획, AI·결제, 브라우저 렌더링, 운영 알림 연결은 이번 검사 범위 밖이다. 신원 캐시에 포함된 관리자 상태는 같은 Request에서 최대 5초 재사용하며, 일반 유료 이용권은 매번 다시 조회한다.

재현할 때 `npm run test:team`과 `npm run benchmark:team`을 사용한다. 측정기는 새 이름의 JSON을 만들고 기존 최종 결과 덮어쓰기를 거절한다. Redis 검사는 로컬 테스트 Redis를 먼저 실행해야 한다.

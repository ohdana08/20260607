# 딱지원핏 IR 피치덱·사업계획서 범용 시각화 검증보고서

작성일: 2026-09-03

검증 범위: 범용 스타트업 IR 및 사업계획서
제외 범위: 딥테크 전용 TRL, 특허/FTO, 인증, 임상·기술성능 검증

## 1. 결론

딱지원핏의 시각화는 **사업계획서에 실제로 들어 있는 내용**을 출발점으로 삼아야 한다. 그중 출처·증빙·산식으로 검증된 사실만 시각화할 수 있다. 검증되지 않았거나 증거가 더 필요한 주장은 시각화하면 안 된다.

따라서 딱지원핏에는 시각화가 더 필요하지만, 모든 문서에 TAM/SAM/SOM, 경쟁표, 포지셔닝 맵을 기계적으로 넣으면 오히려 신뢰도가 떨어진다.

필요한 것은 **시각화 템플릿 묶음 + 선택 엔진**이다. 각 슬라이드마다 다음 순서로 판단해야 한다.

> 사업계획서의 주장 → 연결된 증빙 확인 → 검증 통과 → 가장 적합한 시각화 생성

> 검증 실패 또는 증빙 부족 → 시각화 생성 금지 → 필요한 자료와 보완방법 안내

덱 전체에는 보통 8~12개의 핵심 시각자료가 충분하다. 한 슬라이드에는 원칙적으로 핵심 주장 1개와 그 주장을 증명하는 시각자료 1개만 둔다. 나머지 상세 표와 산식은 부록으로 보낸다.

검토 시작 시점의 딱지원핏은 TAM/SAM/SOM, 프로세스, 경쟁비교, 고객여정, 수익모델, 로드맵, 퍼널을 만들 수 있었지만, “이 사업계획서에서 어떤 내용이 검증되었으며, 무엇을 시각화해도 되는가”를 먼저 판정하는 공통 게이트가 완전하지 않았다. traction·가격/마진·재무·포지셔닝 등 핵심 유형도 여전히 후속 보강 대상이다.

## 2. IR의 흐름에는 하나의 고정 정답이 없다

[YC](https://www.ycombinator.com/blog/this-brief-guide-is-a-summary-of-what-startup-founders-need-to-know-about-raising-the-seed-funds-critical-to-getting-their-company-off-the-ground)는 피치덱에 정해진 형식이나 순서가 없다고 설명한다. 반면 [Sequoia](https://sequoiacap.com/article/writing-a-business-plan)는 회사 목적 → 문제 → 해결책 → Why now → 시장 → 경쟁 → 사업모델 → 팀 → 재무 → 비전이라는 대표 흐름을 제시한다. 따라서 딱지원핏은 순서를 하나로 고정하기보다 발표 목적과 보유 증거에 따라 재배열해야 한다.

범용 기본 흐름은 다음이 가장 안정적이다.

| 순서 | 심사자·투자자의 질문 | 핵심 내용 | 우선 시각화 |
|---:|---|---|---|
| 1 | 한 문장으로 무엇을 하는가? | 고객·문제·해결·효과 | 제품 대표 이미지 또는 가장 강한 숫자 |
| 2 | 문제가 실제로 크고 자주 생기는가? | 고객, 발생 장면, 빈도·비용 | 현재 업무 흐름·고객여정 또는 정량 차트 |
| 3 | 왜 지금인가? | 시장·기술·제도·행동 변화 | 2~3개 추세선 또는 변화 타임라인 |
| 4 | 어떻게 해결하는가? | 사용 전후, 핵심 가치 | Before/After 또는 입력→처리→결과 |
| 5 | 실제 제품은 무엇인가? | 핵심 기능과 사용 장면 | 실제 화면·서비스 블루프린트 |
| 6 | 사람들이 원한다는 증거가 있는가? | 인터뷰, 신청, 파일럿, 매출, 재구매 | 검증 사다리·시계열·퍼널·코호트 |
| 7 | 시장은 얼마나 크고 어디부터 잡는가? | TAM/SAM/SOM, 첫 세그먼트 | 산식형 시장 퍼널 + beachhead 확장도 |
| 8 | 누가 얼마를 왜 지불하는가? | 고객·사용자·지불자, 가격, 마진 | 돈의 흐름 + 단위경제 |
| 9 | 첫 고객을 어떻게 확보하는가? | ICP, 채널, 전환, 영업주기 | GTM 퍼널·채널 비교·플라이휠 |
| 10 | 왜 경쟁대신 우리를 선택하는가? | 직접·간접 대안, 구매기준 | 근거형 경쟁표 또는 측정형 포지셔닝 맵 |
| 11 | 앞으로 무엇을 달성하는가? | 기간별 목표·자금·성과 | 마일스톤 로드맵 + 자금-성과 연결 |
| 12 | 누가 실행하며 무엇을 요청하는가? | 팀 적합성, 요청금액, 용도 | 역량-과제 매핑 + Use of Funds |

강한 traction이 있으면 6번을 3~4번으로 당긴다. 초기 아이디어 단계라면 매출 그래프 대신 고객 인터뷰, LOI, 사전신청, 유료 파일럿 등 검증의 강도를 보여준다. 정부지원 발표에서는 요청 자금과 기간 내 산출물을 더 앞세우고, 투자 IR에서는 성장률·unit economics·회수 가능한 시장을 더 앞세운다.

## 3. 필수에 가까운 범용 시각화

### 3.1 문제 구조·현재 고객여정

- 목적: 문제를 추상적 문장이 아닌 발생 장면으로 보여준다.
- 형태: `상황 → 행동 → 병목 → 손실 → 기존 우회방법`.
- 필요한 입력: 실제 고객군, 문제 발생 빈도, 시간·비용·오류, 인터뷰 또는 운영기록.
- 생성 금지: 근거 없이 만든 가상 페르소나와 감정 점수.

### 3.2 솔루션 Before/After

- 목적: 기능 목록 대신 변화의 크기를 보여준다.
- 형태: 기존 5단계가 2단계로 줄어드는 흐름, 시간·비용·정확도 전후 비교.
- 필요한 입력: 기존 방식, 새 방식, 동일 측정기준.
- 생성 금지: 전후 측정조건이 다른 수치 비교.

### 3.3 제품 화면 또는 서비스 작동 흐름

- 목적: “실제로 무엇을 파는가”를 한눈에 이해시킨다.
- 형태: 실제 화면 1~3개, 입력→처리→출력, 사용자·운영자 역할 구분.
- 필요한 입력: 실제 캡처, 프로토타입, 기능 상태.
- 생성 금지: 존재하지 않는 기능을 완성 화면처럼 표현.

### 3.4 검증·Traction

- 목적: 수요와 실행력을 보여준다.
- 형태는 단계에 따라 다르다.
  - 아이디어: 인터뷰 → 문제확인 → LOI/사전신청 → 파일럿
  - 초기매출: 월별 매출·고객·재구매·파이프라인
  - 성장단계: 성장률·유지율·코호트·CAC 회수
- 필요한 입력: 값, 기간, 모집단, 정의, 증빙.
- 생성 금지: 로고 모음을 traction으로 부르기, 누적값만으로 최근 성장처럼 보이기.

### 3.5 TAM/SAM/SOM과 Beachhead

- 목적: 전체 시장의 크기보다 실제 진입 가능한 시장을 설명한다.
- 검증 근거: [GOV.UK Investor Readiness Essentials](https://www.gov.uk/government/publications/unlocking-space-for-investment-growth-hub/track-1-investor-readiness-essentials)는 TAM·SAM·SOM이 논리적으로 연결되고, SOM은 전략·자원·성과로 뒷받침되어야 한다고 설명한다.
- 권장 형태: 단순 동심원보다 `정의 + 산식 + 숫자 + 출처`가 보이는 퍼널·워터폴.
- 필수 입력:
  - TAM = 전체 대상 수 × 연간 지출 또는 총 시장 매출
  - SAM = 제품·지역·고객 조건에 맞는 대상 수 × 객단가
  - SOM = 초기 목표계정 수 × 연간 계약금액 × 현실적 획득률
  - 기준연도, 통화, 출처, 중복 제거 기준
- 보조 시각화: 첫 고객군 → 인접 세그먼트 → 확장시장.
- 생성 금지: 원 3개와 큰 숫자만 제시, SOM을 근거 없는 시장점유율로 계산.

### 3.6 수익모델과 Unit Economics

- 목적: 누가 누구에게 무엇을 받고 얼마를 지불하는지 보여준다.
- 기본 형태: `고객/지불자 → 제품·서비스 → 우리 회사 → 파트너/비용`의 돈 흐름.
- 사업모델별 분기:
  - SaaS: 요금제, ACV/ARPA, 총마진, 유지율, CAC 회수기간
  - 마켓플레이스: GMV → take rate → 순매출, 공급·수요 흐름
  - 커머스/하드웨어: 판매단가 → 원가 → 총마진, 반복구매·소모품
  - 광고/제휴: 트래픽 → 전환 → 광고주·파트너 매출
- 생성 금지: 가격과 원가가 가정인데 확정치처럼 표시, 매출항목만 나열하고 돈의 흐름을 생략.

### 3.7 GTM·고객획득

- 목적: 시장이 아니라 실제 고객에게 도달하는 경로를 보여준다.
- 형태: `ICP → 채널 → 리드 → 상담/체험 → 유료전환 → 유지/추천`.
- 필요한 입력: 채널별 리드, 전환율, 영업기간, 획득비용, 담당 주체.
- 데이터가 없을 때: 계획 퍼널로 표시하고 목표치와 검증 일정을 분리한다.
- 생성 금지: SNS, 광고, 제휴 같은 채널명만 나열.

### 3.8 경쟁우위표

- 목적: 구매자가 대안을 고를 때 쓰는 기준으로 비교한다.
- 비교 대상: [SBA 경쟁분석 가이드](https://www.sba.gov/es/guia-de-negocios/planifique-su-empresa/investigacion-de-mercado-y-analisis-competitivo)의 원칙처럼 직접 경쟁사뿐 아니라 수작업, 엑셀, 외주, 무사용 같은 간접 대안도 포함한다.
- 행: 고객이 중요하게 여기는 4~6개 기준.
- 셀: 체크표시보다 측정값, 조건, 실제 기능 여부.
- 필요한 입력: 경쟁사 공식자료·가격·테스트 결과·고객 인터뷰와 날짜.
- 생성 금지: 우리만 전부 체크, 경쟁사를 의도적으로 좁게 선택, 근거 없는 “우수”.

### 3.9 포지셔닝 맵

- 목적: 시장에서 차지하려는 자리를 빠르게 보여준다.
- 사용 조건: 두 축이 고객의 구매결정에 중요하고 실제로 측정 가능할 때만 사용한다.
- 좋은 축: 도입기간(일), 연간 총비용(원), 자동화율(%), 지원범위(개수)처럼 단위가 있는 축.
- 나쁜 축: 혁신성, 편리함, AI 수준처럼 주관적인 축.
- 원칙: 메인 덱에서는 경쟁표와 포지셔닝 맵 중 더 증거가 강한 하나를 선택한다. 상세판은 부록에 둔다.

### 3.10 로드맵·자금 사용

- 목적: 돈이 어떤 리스크를 줄이고 어떤 성과를 만드는지 보여준다.
- 형태: `기간 → 실행 → 산출물 → KPI → 담당 → 예산`.
- Use of Funds는 단순 원형그래프보다 `투입금 → 마일스톤 → 성과지표` 연결형이 낫다.
- 생성 금지: 기능 출시 달력만 제시, 인건비·마케팅비 비율만 보이고 결과를 생략.

## 4. 조건부 시각화

| 시각화 | 넣는 조건 | 빼는 조건 |
|---|---|---|
| Why-now 추세선 | 시장·비용·규제·행동 변화가 수치로 확인됨 | 출처 없는 유행어뿐임 |
| 코호트 차트 | 반복사용·구독·재구매 데이터가 있음 | 일회성 거래 중심 또는 표본이 너무 작음 |
| 플라이휠 | 한 사용자의 행동이 다음 성장과 방어력을 실제로 강화함 | 단순 선순환 문구뿐임 |
| 채널 비교표 | 여러 채널의 CAC·전환·기간을 비교 가능 | 아직 채널 실험 전임 |
| 3~5년 재무그래프 | 매출동인과 비용가정이 있음 | 근거 없는 하키스틱만 가능함 |
| 조직도 | 다수 부서·파트너 역할이 실행에 중요 | 초기 소수 팀이라 구조가 자명함 |
| 임팩트 차트 | 사회·환경 성과가 평가·구매기준임 | 사업성과와 연결되지 않은 홍보성 수치 |

## 5. 딱지원핏이 보유한 것과 부족한 것

검토 시작 시점의 코드상 생성 후보는 다음과 같았다.

- TAM/SAM/SOM
- 사업 운영 프로세스
- 경쟁우위 비교표
- 고객 여정
- 수익모델 항목도
- 실행 로드맵
- 마케팅 퍼널(호환용)

근거 ID가 없으면 생성을 막는 방향은 옳았지만, 검토 시작 시점에는 유형별 증거 게이트가 서로 달랐다.

- TAM/SAM/SOM: 근거 ID가 있어야 생성
- 경쟁표: 모든 비교 행에 근거 ID가 있어야 생성
- 로드맵: 근거 ID와 출처 메모가 모두 있어야 생성
- 프로세스·고객여정·수익모델·퍼널: 근거 ID가 없어도 출처 메모만 있으면 생성 가능

마지막 조건은 사용자가 정한 원칙보다 느슨했다. 단순한 출처 메모가 해당 주장의 검증을 의미하지는 않기 때문이다. 이번 구현에서는 모든 유형에 대해 `evidenceStatus=verified`이며 서버가 검증한 근거 ID와 실제로 연결된 경우에만 시각화하도록 공통 게이트를 적용했다. 출력은 최대 6개이고, 검증되지 않은 유형은 발표자료에서 제외 사유를 명시한다.

우선 보강해야 할 범용 시각화는 다음 8개다.

1. 문제 정량화·현재업무 병목
2. Before/After
3. 실제 제품 화면 또는 서비스 작동도
4. 단계별 traction
5. 산식형 TAM/SAM/SOM과 beachhead
6. 돈의 흐름 + 가격·마진·단위경제
7. 측정 가능한 포지셔닝 맵
8. 매출동인 기반 재무와 자금-성과 연결

## 6. 딱지원핏 선택 엔진 제안

선택 엔진 앞에 반드시 **시각화 자격 검증 단계**를 둔다.

1. 사업계획서에 해당 주장이 실제로 존재하는가?
2. 주장이 원문 증빙·통계·계약·매출자료·사용자 제공 문서와 연결되어 있는가?
3. 수치의 정의·단위·기간·산식이 확인되는가?
4. 실제 실적과 향후 계획이 구분되어 있는가?
5. 위 조건을 통과한 경우에만 적합한 시각화 유형을 선택한다.

하나라도 통과하지 못하면 이미지를 생성하지 않고 `증빙 부족`, `산식 필요`, `기준기간 필요`처럼 보완 요청을 반환한다.

각 후보 시각화에 아래 필드를 갖게 해야 한다.

| 필드 | 의미 |
|---|---|
| `question` | 이 시각화가 답하는 평가 질문 |
| `claim` | 한 문장 핵심 주장 |
| `visualType` | 표, 퍼널, 타임라인, 흐름도, 시계열, 산점도 등 |
| `requiredData` | 반드시 필요한 입력값 |
| `evidenceIds` | 원문·인터뷰·통계·증빙 연결 |
| `formula` | 시장·재무·전환 계산식 |
| `periodAndUnit` | 기준기간과 단위 |
| `actualOrPlan` | 실적과 계획 구분 |
| `confidence` | 확인·가정·자료부족 |
| `doNotGenerateReason` | 생성하지 못한 이유와 필요한 보완자료 |

선택 점수는 다음처럼 계산할 수 있다.

> 관련성 30 + 증거충분성 30 + 이해개선 20 + 평가중요도 20 - 중복 20 - 오해위험 30

그리고 다음 하드게이트를 둔다.

- 수치형 차트: 단위·기간·출처·산식 중 하나라도 없으면 생성 금지
- 모든 시각화: 사업계획서의 주장과 증빙 ID가 연결되지 않으면 생성 금지
- 경쟁표: 각 핵심 행의 근거가 없으면 생성 금지
- 포지셔닝 맵: 축 정의와 측정근거가 없으면 생성 금지
- 실적 차트: 실제와 계획이 섞이면 생성 금지
- 제품 화면: 구현되지 않은 기능은 목업·예정으로 명시

## 7. 현재 발표자료에서 확인된 문제

현재 샘플 발표자료는 시장, 경쟁, 수익모델, GTM, 로드맵 슬라이드가 대부분 텍스트 중심이고 동일한 시장 설명이 반복된다. 시장은 TAM/SAM/SOM의 정의·산식·진입 세그먼트가 부족하고, 경쟁은 근거형 표나 포지셔닝이 없으며, 수익모델은 가격 가정과 돈의 흐름·마진이 분리되어 있지 않다. GTM과 로드맵도 전환·비용·성과 마일스톤보다 일반적인 단계 설명에 가깝다.

따라서 현재 수준은 “정보를 PPT에 옮긴 초안”으로는 쓸 수 있지만, “심사자가 비교하고 판단하게 만드는 시각적 IR”로는 부족하다.

## 8. 구현 우선순위

### 1단계 — 기존 7종을 고친다

- TAM/SAM/SOM: 동심원 중심에서 산식형으로 변경
- 수익모델: 항목 나열에서 고객·지불자·파트너 돈 흐름으로 변경
- 퍼널: 단계명뿐 아니라 수량·전환율·기간을 표시
- 로드맵: 산출물·KPI·예산 연결
- 경쟁표: 체크표시보다 측정값과 출처 날짜 표시

### 2단계 — 필수 5종을 추가한다

- 문제 병목/고객여정
- Before/After
- 제품 화면 프레임
- traction 시계열·검증 사다리
- 포지셔닝 맵

### 3단계 — 사업모델별 분기를 추가한다

- SaaS, 마켓플레이스, 커머스/하드웨어, 광고/제휴
- 각 모델에 맞는 가격·마진·유지·전환 지표만 선택

### 4단계 — 덱 품질검사를 자동화한다

- 같은 문장·근거의 반복 탐지
- 슬라이드별 핵심 주장 1개 검사
- 모든 숫자의 단위·기간·출처 확인
- 실제·계획·가정의 시각적 구분
- 차트가 없는 이유와 추가자료 요청 자동 출력

## 9. 하지 말아야 할 것

- 모든 덱에 동일한 6개 차트를 자동 삽입
- 산식 없는 TAM/SAM/SOM 동심원
- 우리만 오른쪽 위에 놓는 주관적 포지셔닝 맵
- 우리만 전부 체크된 경쟁표
- 원인 없이 상승하는 하키스틱 매출
- 고객사 로고만 나열한 traction
- 단위가 다른 항목을 한 레이더차트에 합치기
- 결과 없이 비목만 나눈 Use of Funds 원형그래프
- AI가 만든 장식 이미지를 실제 제품·검증자료처럼 사용
- 한 슬라이드에 표·퍼널·타임라인을 동시에 넣기

## 10. 최종 판정

딱지원핏의 시각화 기능은 기초 후보군을 바탕으로 **근거가 확인된 자료만 그리는 1차 공통 게이트**까지 구현됐다. 다음 단계의 핵심 개선은 템플릿 수보다 다음 네 가지다.

1. 사업계획서 주장과 증빙의 연결 여부를 먼저 검증
2. 검증을 통과한 자료만 업종·사업모델·단계에 맞춰 시각화
3. 차트마다 출처·산식·실적/계획 구분을 강제
4. 데이터가 없을 때 꾸며내지 않고 필요한 자료를 요청

이 네 가지 중 1~2번과 기본적인 3~4번 통제가 이번 작업에 반영됐다. 후속으로 업종별 산식 검증과 traction·가격/마진·재무·포지셔닝 템플릿을 확장하면 “근거를 시각적으로 조직하는 사업계획서·IR 생성기”의 범용성이 높아진다.
